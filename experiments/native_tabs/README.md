# Native document-session architecture proof — NOT validated yet

Base: LUNA b60f5f2529760102887fa660365f037e78fc7aae.
Upstream: PDF4QT 67b6b9903cb4e318803342f2d428f02e1bb124e3.

This is candidate B: one Qt process, one native QMainWindow, one complete
PDFEditorMainWindow/controller/object tree per QTabWidget page. No foreign HWND,
no IPC, no document reload on switching. Production LUNA library, thumbnail and
memo sources are unchanged. This executable is not installed or released.

The nine bundled plugins expose their existing default constructors through
Q_INVOKABLE. With the proof's lunaNativeSessions property, loadPlugins uses
root->metaObject()->newInstance(), parents the new object to its controller,
and never binds the DLL root. Missing factories terminate startup; shared-object
fallback is forbidden. Old unpatched DLLs must not be mixed into the package.
The PDFPlugin virtual ABI is unchanged, but every bundled plugin must be rebuilt.

Small pinned-source corrections also cover busy-close OR/AND, plugin-only dirty
state, explicit save result propagation, embedded-window settings writes, and
Qt::Popup global placement. Source pin and unique-anchor checks fail closed.
Plugin modules use Qt's default PreventUnloadHint; do not add runtime unloading
while sessions exist. Session/plugin teardown remains a required runtime gate.

Run the existing manual Windows workflow on this isolated branch with
native_tabs_proof=true and all other options at defaults. It applies the ordinary
LUNA overlay first, then prepare.py, compiles the full pinned project, and runs
the proof at Qt process scales 1, 1.25 and 1.5. Evidence is uploaded on failure as
well. A proof build cannot overwrite the baseline engine cache or upload a
standard portable artifact. No main merge or public Release.

Acceptance requires process exit 0 and summary.json accepted=true. A compile
PASS, source PASS, or absent report is never runtime acceptance. The tests cover:

- two controllers/documents and nine distinct plugin/action sets in one main window;
- forty switches without document replacement and independent zoom;
- actual Win32 Ctrl+F and Unicode typing with distinct alpha/bravo results;
- plugin-only pending editing and close Cancel;
- native Qt highlighter gestures, 1/2 annotations, isolated save and reopen;
- real Windows file-lock save failure with dirty state/data retained;
- close Cancel, Discard, Save, deferred deletion, surviving-tab search and reopen.

Highlighter pointer gestures and dialog responses use Qt events/fixture timers.
They exercise the real Editor but are not physical mouse/native file-dialog QA.
All plugin functions, production library integration, Save As identity migration,
long sessions and physical monitor DPI remain unverified even if these gates pass.
Only the disposable PDFs generated by run_windows.py may be used for this proof.

## Production handoff after acceptance

1. Keep an app shell and document-session registry. Route open/drop/recent/link
   requests to the registry; never replace a loaded session on a new-file request.
2. Replace IndependentDocuments process launch/activation adapter, retaining
   canonical-path deduplication and cross-process document claims. Do not change
   thumbnail, memo, metadata or file-move behavior.
3. Keep LibraryPanel alive once; change its fixed window/controller binding to an
   active-session accessor. Disconnect only active-document signals when switching.
   Folder/root/filter/memo state belongs to the library; pages/zoom/search/undo/
   annotation/tool/plugin state belongs to each document session.
4. Preserve each Editor's actions/menus/docks in its tab first. Share chrome only
   after core behavior passes; no central-widget extraction that loses owner state.
5. Treat global author, execution strategy, theme, shortcuts and settings as app
   preferences. Do not allow hidden controllers to overwrite app-wide preferences.
6. Add save-as path reservation and commit/release, pending-load failure rollback,
   busy-worker cancellation, destruction and multi-tab close tests before shipping.
